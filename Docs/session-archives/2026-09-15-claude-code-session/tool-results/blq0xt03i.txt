Collect the entity names from the chosen scope. Before designing anything, search `Docs/file-map.md` and `Domain/Entities/` for each name. Split the list into `existing` and `new`. Existing entities are read, never regenerated. Only extend them if a feature spec needs a field they lack, and say so.

## Step 2. Design each entity

For every new entity, decide and write in chat:

| Aspect | Rule |
|---|---|
| Kind | `struct` by default. `final class` only with a written reason (identity semantics, reference sharing). |
| Identity | `let id: <Entity>ID` where `<Entity>ID` is a typed wrapper around UUID or String. Never bare `UUID` as a field type. |
| Fields | Named, typed, minimal. No optional unless absence is a real state. |
| Value objects | Any field with validation rules (email, money, percentage, phone) becomes a value object with a failable or throwing initialiser. |
| Invariants | Rules that must always hold. Enforced in the initialiser or a mutating method. Listed explicitly. |
| Conformances | `Equatable`, `Hashable`, `Sendable`, `Identifiable`. `Codable` only if the entity itself crosses a boundary, otherwise DTOs handle it. |
| Relationships | By ID reference, never by embedding another entity unless composition is intrinsic. |

Flag shared entities (used by two or more features) and assign one owning feature folder.

## Step 3. Design errors and repository protocols

For each feature in scope, one `<Noun>Error` enum in `Domain/Errors/`:

```swift
enum InvoiceError: Error, Equatable, Sendable {
    case notFound(InvoiceID)
    case invalidAmount
    case alreadyPaid
    case storage(underlying: String)
}
```

For each aggregate root, one repository protocol in `Domain/Repositories/<Feature>/`:

```swift
protocol InvoiceRepository: Sendable {
    func fetchAll() async throws(InvoiceError) -> [Invoice]
    func fetch(id: InvoiceID) async throws(InvoiceError) -> Invoice
    func save(_ invoice: Invoice) async throws(InvoiceError)
    func delete(id: InvoiceID) async throws(InvoiceError)
}
```

Use typed throws when Swift 6 is set in conventions.md. Otherwise plain `throws` with the error documented.

Present all entities, value objects, errors and protocols in chat as Swift. Call AskUserQuestion to approve. Iterate, maximum 3 rounds.

## Step 4. Write the files

One file per type, at the path dictated by conventions.md:

- `Domain/Entities/<Feature>/<Entity>.swift`
- `Domain/Entities/<Feature>/<Entity>ID.swift`
- `Domain/ValueObjects/<ValueObject>.swift`
- `Domain/Errors/<Noun>Error.swift`
- `Domain/Repositories/<Feature>/<Noun>Repository.swift`

File header on every file:

```swift
// <Name>.swift
// Layer: Domain
// Purpose: <one line>
```

Only `import Foundation`. Nothing else. Every file must compile alone.

Register each file in `Docs/file-map.md`. If a stub already existed from file-structure-organizer, fill it in place. Never create a sibling.

## Step 2. Write the rules table

Every rule gets an ID and a home before any code:

```
| ID | Rule (plain language) | Inputs | Output | Home | Feature |
|---|---|---|---|---|---|
| R-01 | An invoice cannot be paid twice | Invoice.status | InvoiceError.alreadyPaid | Invoice.markPaid() | Invoices |
| R-02 | Total = sum(lines) + VAT, rounded to 2 decimals | [InvoiceLine], VATRate | Money | InvoiceTotalCalculator | Invoices |
```

Home decision:
- Rule touches one entity's own state: entity method (mutating or computed)
- Rule touches several entities or needs a policy: domain service in `Domain/Services/<Feature>/<Name>.swift`
- Rule is a pure calculation: `struct <Name>Calculator` with a single `calculate` method, stateless

Call AskUserQuestion to approve the table. Iterate, maximum 3 rounds.

## Step 3. Implement

Entity methods are added to the existing entity file, or to `<Entity>+Rules.swift` next to it if the entity file would exceed 150 lines.

Domain services:

```swift
// InvoiceTotalCalculator.swift
// Layer: Domain
// Purpose: R-02 invoice total with VAT

import Foundation

struct InvoiceTotalCalculator: Sendable {
    func calculate(lines: [InvoiceLine], vatRate: VATRate) -> Money {
        let subtotal = lines.reduce(Money.zero) { $0 + $1.amount }
        return subtotal.applying(vatRate).rounded(scale: 2)
    }
}
```

Every rule implementation carries its rule ID in the Purpose line. No rule without an ID. No ID without a test (test-generator reads this table).

If a rule needs data the entity does not have, stop and say which field is missing. Do not add fields silently. Send the user to domain-modeler.

```swift
// CreateInvoiceUseCase.swift
// Layer: Domain
// Purpose: Create an invoice for a client applying R-02

import Foundation

protocol CreateInvoiceUseCase: Sendable {
    func execute(_ input: CreateInvoiceInput) async throws(InvoiceError) -> Invoice
}

struct CreateInvoiceInput: Sendable, Equatable {
    let clientID: ClientID
    let lines: [InvoiceLine]
    let vatRate: VATRate
}
```

`Domain/UseCases/<Feature>/Default<Verb><Noun>UseCase.swift`:

```swift
// DefaultCreateInvoiceUseCase.swift
// Layer: Domain
// Purpose: Default implementation of CreateInvoiceUseCase

import Foundation

struct DefaultCreateInvoiceUseCase: CreateInvoiceUseCase {
    private let invoices: InvoiceRepository
    private let clients: ClientRepository
    private let calculator: InvoiceTotalCalculator

    init(invoices: InvoiceRepository, clients: ClientRepository, calculator: InvoiceTotalCalculator) {
        self.invoices = invoices
        self.clients = clients
        self.calculator = calculator
    }

    func execute(_ input: CreateInvoiceInput) async throws(InvoiceError) -> Invoice {
        _ = try await clients.fetch(id: input.clientID).mapError(InvoiceError.init)
        let total = calculator.calculate(lines: input.lines, vatRate: input.vatRate)
        let invoice = Invoice(id: InvoiceID(), clientID: input.clientID, lines: input.lines, total: total, status: .draft)
        try await invoices.save(invoice)
        return invoice
    }
}
```

Rules for the body:
- One `execute` method. Exactly one.
- All dependencies are protocols, injected via `init`.
- Input is a dedicated `<Verb><Noun>Input` struct when more than one parameter. Defined in the protocol file.
- No formatting, no UI state, no logging framework.
- Cross-feature reads go through the other feature's repository protocol, never its use case, unless composition is explicit in architecture.md.

If a use case needs a rule not in the rules table, stop and redirect to business-logic-engine. If it needs a repository method that does not exist, stop and redirect to domain-modeler.

## Step 3. Generate

Files, one type each, under the paths from conventions.md:

- `Data/Repositories/<Feature>/<Noun>RepositoryImpl.swift`

Repository implementation shape:

```swift
// InvoiceRepositoryImpl.swift
// Layer: Data
// Purpose: InvoiceRepository over remote API with local cache

import Foundation

final class InvoiceRepositoryImpl: InvoiceRepository {
    private let remote: InvoiceRemoteDataSource
    private let local: InvoiceLocalDataSource
    private let mapper: InvoiceMapper

    init(remote: InvoiceRemoteDataSource, local: InvoiceLocalDataSource, mapper: InvoiceMapper = InvoiceMapper()) {
        self.remote = remote
        self.local = local
        self.mapper = mapper
    }

    func fetchAll() async throws(InvoiceError) -> [Invoice] {
        do {
            let dtos = try await remote.fetchAll()
            let invoices = dtos.map(mapper.toDomain)
            try await local.replaceAll(invoices.map(mapper.toModel))
            return invoices
        } catch let error as URLError where error.code == .notConnectedToInternet {
            return try await local.fetchAll().map(mapper.toDomain)
        } catch {
            throw InvoiceError.storage(underlying: String(describing: error))
        }
    }
}
```

Rules for bodies:
- Every external error is mapped to the feature's domain error. Nothing else crosses the boundary.
- Mappers are pure. No async, no side effects, tested by test-generator.
- No business rule in Data. If a rule is needed, redirect to business-logic-engine.
- SwiftData `@Model` classes never leave Data. Domain sees entities only.

```
InvoiceListViewModel
  State:
    phase: Phase (.idle | .loading | .loaded([InvoiceRowItem]) | .empty | .failed(message: String))
    searchQuery: String

  Derived:
```

## Step 3. Generate

`@Observable` mode (iOS 17+):

```swift
// InvoiceListViewModel.swift
// Layer: Presentation
// Purpose: State and actions for the invoice list screen

import Foundation
import Observation

@MainActor
@Observable
final class InvoiceListViewModel {
    enum Phase: Equatable {
        case idle, loading, empty
        case loaded([InvoiceRowItem])
        case failed(message: String)
    }

    private(set) var phase: Phase = .idle
    var searchQuery = ""
    private(set) var isRefreshing = false

    var filteredItems: [InvoiceRowItem] {
        guard case .loaded(let items) = phase else { return [] }
        guard !searchQuery.isEmpty else { return items }
        return items.filter { $0.title.localizedCaseInsensitiveContains(searchQuery) }
    }

    private let fetchInvoices: FetchInvoicesUseCase
    private let deleteInvoice: DeleteInvoiceUseCase
    private weak var coordinator: (any InvoicesNavigating)?

    init(fetchInvoices: FetchInvoicesUseCase, deleteInvoice: DeleteInvoiceUseCase, coordinator: any InvoicesNavigating) {
        self.fetchInvoices = fetchInvoices
        self.deleteInvoice = deleteInvoice
        self.coordinator = coordinator
    }

    func load() async {
        phase = .loading
        await fetch()
    }

    func refresh() async {
        isRefreshing = true
        defer { isRefreshing = false }
        await fetch()
    }

    func delete(id: InvoiceID) async {
        do {
            try await deleteInvoice.execute(id)
            await fetch()
        } catch {
            phase = .failed(message: Self.message(for: error))
        }
    }

    func select(id: InvoiceID) {
        coordinator?.navigate(to: .detail(id))
    }

    func tapCreate() {
        coordinator?.navigate(to: .create)
    }

    private func fetch() async {
        do {
            let invoices = try await fetchInvoices.execute()
            phase = invoices.isEmpty ? .empty : .loaded(invoices.map(InvoiceRowItem.init))
        } catch {
            phase = .failed(message: Self.message(for: error))
        }
    }

    private static func message(for error: InvoiceError) -> String {
        switch error {
        case .notFound: String(localized: "invoice.error.notFound")
        case .storage: String(localized: "invoice.error.storage")
        default: String(localized: "error.generic")
        }
    }
}
```

`ObservableObject` mode (iOS 16): same structure with `final class X: ObservableObject`, `@Published private(set) var`, and no `import Observation`.

Rules for the body:
- `@MainActor` always.
- Setters of state are `private(set)`. Only the ViewModel mutates its state.
- No `import SwiftUI`. Foundation and Observation only.
- No direct repository access. Use cases only.
- No `Task { }` inside the ViewModel. Actions are `async`, the View owns the task.
- Strings come from the String Catalog when conventions.md says catalog mode.

Write `<Screen>+Models.swift` for presentation models, with `init(_ entity:)` mapping from the domain entity. Number and date formatting happens here, once.

```swift
// InvoiceListView.swift
// Layer: Presentation
// Purpose: Invoice list screen bound to InvoiceListViewModel

import SwiftUI

struct InvoiceListView: View {
    @State private var viewModel: InvoiceListViewModel

    init(viewModel: InvoiceListViewModel) {
        _viewModel = State(initialValue: viewModel)
    }

    var body: some View {
        DSScreen(title: String(localized: "invoices.title")) {
            content
        }
        .searchable(text: $viewModel.searchQuery)
        .refreshable { await viewModel.refresh() }
        .toolbar {

                DSIconButton(icon: .plus, label: String(localized: "invoices.create")) {
                    viewModel.tapCreate()
                }
            }
        }
        .task { await viewModel.load() }
    }

    @ViewBuilder
    private var content: some View {
        switch viewModel.phase {
        case .idle, .loading:
            DSLoadingView()
        case .empty:
            DSEmptyState(title: String(localized: "invoices.empty"), actionTitle: String(localized: "invoices.create")) {
                viewModel.tapCreate()
            }
        case .loaded:
            List(viewModel.filteredItems) { item in

                    .contentShape(Rectangle())
                    .onTapGesture { viewModel.select(id: item.id) }
                    .swipeActions { deleteButton(for: item.id) }
            }
            .listStyle(.plain)
        case .failed(let message):
            DSErrorState(message: message) {
                Task { await viewModel.load() }
            }
        }
    }

    private func deleteButton(for id: InvoiceID) -> some View {
        Button(role: .destructive) {
            Task { await viewModel.delete(id: id) }
        } label: {
            Label(String(localized: "common.delete"), systemImage: "trash")
        }
    }
}
```

## Step 3. Generate the feature coordinator

```swift
// InvoicesCoordinator.swift
// Layer: Presentation
// Purpose: Owns the Invoices navigation stack and builds its screens

import SwiftUI
import Observation

@MainActor
@Observable
final class InvoicesCoordinator: InvoicesNavigating {
    var path = NavigationPath()
    var modal: InvoicesModal?

    private let container: AppContainer

    init(container: AppContainer) {
        self.container = container
    }

    func navigate(to route: InvoicesRoute) {
        switch route {
        case .list: path = NavigationPath()
        case .detail(let id): path.append(InvoicesRoute.detail(id))
        case .create: modal = .create
        case .edit(let id): path.append(InvoicesRoute.edit(id))
        }
    }

    func pop() { if !path.isEmpty { path.removeLast() } }
    func dismissModal() { modal = nil }

    @ViewBuilder
    func view(for route: InvoicesRoute) -> some View {
        switch route {
        case .list: InvoiceListView(viewModel: container.makeInvoiceListViewModel(coordinator: self))
        case .detail(let id): InvoiceDetailView(viewModel: container.makeInvoiceDetailViewModel(id: id, coordinator: self))
        case .create: InvoiceFormView(viewModel: container.makeInvoiceFormViewModel(mode: .create, coordinator: self))
        case .edit(let id): InvoiceFormView(viewModel: container.makeInvoiceFormViewModel(mode: .edit(id), coordinator: self))
        }
    }
}
```
