# Scope control

Staying inside the boundary, and resisting the temptation to make the method heavier than the task.

## Two failures, same root

**Scope creep.** An agent sees adjacent improvements constantly. Each is small, plausible and unrequested.
Together they turn a reviewable change into an unreviewable one, and they put the requested fix at the mercy of
changes nobody asked for.

**Over-process.** The method applied at full weight regardless of risk. A one-line fix acquires a gate, a
report, and three documents. This is not caution; it is cost with no return, and it teaches people to bypass the
method entirely — which removes it from the cases that needed it.

Both come from applying a uniform response to a varied world.

## Staying in scope

State the boundary before starting: which paths may change, and what the task is not. Then:

- keep a list — *noticed, not applied* — with one line each;
- report it, do not act on it;
- if something outside the boundary must change for the task to work at all, **stop and say so**. Do not widen
  the boundary silently.

Prove it before committing:

```bash
python3 scripts/scope_audit.py --allow 'docs/**' --allow 'README.md'
```

Exit 1 means something moved outside. That is a finding, not a crash.

## Keeping the method proportionate

Ask before adding ceremony: **what error does this step catch, and what does that error cost?** If you cannot
answer both, drop the step.

| Symptom | Likely over-process |
|---|---|
| A gate with no irreversible or external effect | drop the gate |
| A document nobody will read again | drop the document |
| An evidence level on an unambiguous fact | drop the annotation |
| A backup of something regenerated by a build | drop the backup |
| A hypothesis list for a defect whose cause is known | drop the list |

## When a mandate contradicts itself

It happens: a mandate forbids the only route that would work. The right response is neither to obey to the
letter and fail, nor to route around it quietly. **Say so** — name the prohibition, name the route, explain why
they conflict, and let the human decide. A bounded exception, granted deliberately, is a good outcome. A
prohibition silently bypassed is not.

## A note on refusals

When an improvement is proposed and declined, record the refusal. Otherwise the same suggestion returns on every
pass, and the person has to refuse it again. A refusal is a decision; treat it like one.
