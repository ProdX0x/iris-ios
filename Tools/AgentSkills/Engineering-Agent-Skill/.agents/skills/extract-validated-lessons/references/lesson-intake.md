# Lesson intake

How to decide what a piece of experience is worth, and where it goes.

## The proper-noun test

Delete every product name, framework, tool and person from the candidate rule. Read what remains.

- Still meaningful and actionable → **general**.
- Meaningful only for this platform or problem class → **domain**.
- Meaningless → **case study**, and nothing more.

This single test resolves most candidates, and usually resolves them downward. That is the point: the default
should be that an experience is a story, not a law.

## The recurrence test

| Seen | Status |
|---|---|
| once | a case study; at most a suggestion |
| twice, independently | a candidate general rule |
| repeatedly, across projects | a hard rule |

A single occurrence can feel like a revelation. It is one data point in one context. Write it down as what it
is, and let the second occurrence promote it.

## The cost test

What does following this rule cost, every time, forever? Compare that with the cost of the error it prevents,
multiplied by how often that error would occur.

A rule that costs ten minutes per task to prevent something that happens once a year, and is cheap to fix when
it does, is a net loss. Propose it as a suggestion, or not at all.

## The falsifiability test

Can you state what would show this rule is wrong? If not, it is a preference dressed as a principle. Preferences
are allowed — as suggestions, labelled as such.

## Negative knowledge

Candidates that say what **not** to conclude or do have their own form:

```
CLAIM            what must not be concluded or done
FACT             the observation that forbids it
DATE / SCOPE     when, and where it applies
STILL TRUE IF    the condition under which it stops applying
```

The last line prevents a negative rule outliving its reason and becoming superstition.

## Where things go

| Class | Destination |
|---|---|
| General hard rule | the main skill's hard rules — rare, and only with recurrence |
| General suggestion | the main skill's optional rules |
| Procedure | a reference file |
| Domain rule | a domain skill, marked time-sensitive if the platform can change it |
| Negative knowledge | the negative-knowledge reference, in the four-line form |
| Evidence and narrative | a case study |
| Nothing | discarded, with a line saying it was considered |

## Anti-patterns

- **Every experience becomes a rule.** The commonest failure of retrospectives. It produces a method nobody
  reads.
- **A rule with no failure mode.** Every rule is wrong somewhere. If you cannot say where, you have not
  understood it.
- **A rule that restates another.** Sharpen the original instead.
- **A rule stated universally from one project.** Say "observed once". It costs one word and preserves the
  method's credibility.
- **Only additions.** A cycle with no proposed retirement has skipped the hard half.
